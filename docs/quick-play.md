# Quick Play

Solo remains local and untimed. Quick Play chooses starting chassis before queueing. A single FIFO queue starts when four humans join, or 120 seconds after its oldest waiting cohort begins. Remaining seats get seeded bot profiles. No private rooms, accounts, custom names, chat, skill divisions or progression.

Server owns all drafts, combat outcomes, ranking and HP. Human draft turns receive a fresh 20 seconds; no unused time carries forward. Each consecutive timed-out turn auto-picks and reduces the next allowance by three seconds, with a five-second floor. Any timely manual selection resets the streak and restores 20 seconds for the following round. Disconnects do not pause time; returning via the same browser tab's session token restores the seat. Explicit leave transfers seat to bots immediately. Queue cancellation is free. Inactive queued sessions expire after 20 seconds without polling; all-abandoned matches and finished sessions are eventually cleaned up.

Transport: same-origin HTTP JSON, revision-checked picks, opaque bearer tokens in sessionStorage, 500 ms polling; unchanged revisions return only clock/phase metadata. Only legal actions and public match state are transmitted. No account data, custom names, cross-origin access or chat. Client replays seeded combat with server time and never submits results. Server computes one full deterministic round, publishes its starting state and releases its authoritative result at round end, then advances after three seconds. No continuous position traffic. Slow clients may catch up or skip to authoritative results; visual parity on different phones still needs real testing.

Run: Node 22+, npm start (PORT defaults 3000), open the served URL. npm test covers queue, clocks, reconnect, revision and authorization. Railway serves the same game from main at https://quick-play-production-4fff294f.up.railway.app/ with one replica and /health. The old public GitHub Pages link redirects to the hosted game; local static serving supports Solo only. Ranked and Options are visible but unavailable. In-memory service only: restart loses active queues/matches; 16 match and 256 session safety limits, no persistent accounts or matchmaking history. Session recovery applies to a refresh in the same tab, not an arbitrary device. HTTPS should terminate at hosting provider.

Optional playtest statistics: unchecked launch-menu checkbox; enabling stores only the preference locally. A random in-memory page-session ID groups cumulative foreground seconds (by Solo/Quick Play) and starts/completions/explicit exits; hidden tabs, queue/menu time, paused Solo combat and eliminated spectators do not count. Page refresh creates a new ID. No account, persistent analytics ID, seed, IP, user-agent, game actions or session token is included in the application telemetry. Same-origin /api/playtest validates bounded snapshots and caps accepted events at 600/minute globally. Railway logs contain playtest_session_v1 events; use the greatest seq for each id, never sum cumulative snapshots. The last snapshot is best-effort on hide/exit, with a 60s heartbeat; browser crashes/network errors can undercount and opted-in players are not representative of all visitors. No database or third-party SDK. Hosting log retention and access are managed by Railway; avoid exporting individual session rows publicly.
