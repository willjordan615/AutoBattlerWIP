# Agent development and testing guide

Repository: https://github.com/willjordan615/AutoBattlerWIP
Playable GitHub Pages build: https://willjordan615.github.io/AutoBattlerWIP/
Default branch: main. JavaScript ES modules, Node.js 22+.

## Access and changes
Prefer the connected GitHub integration to read and edit files **directly**. Fetch the latest file and SHA before updating it. Do not clone the repository by default; ask before cloning if direct access is unavailable. Connector permissions are session-specific: this document does not grant tool access.

## Testing without cloning
- The deterministic, DOM-free combat engine is in `src/simulation.js`.
- Drafting, full-match orchestration, persistent HP and combat lifecycle are in `src/headless.js`.
- Bot draft decisions are in `src/draft-ai.js`.
- Browser UI is in `src/game.js`.
- Automated agent-vs-bots playtesting: `node scripts/agent-playtest.js 12 1` (matches, seed).
- Full test suite: `npm test` (GitHub Actions workflow: `.github/workflows/tests.yml`).
- Balance baseline: `npm run balance:report -- 100 strategic 1`; random baseline: `npm run balance:report -- 100 random 1`.

If Node cannot access the repository locally, use the GitHub connector to fetch relevant source files, resolve imports and exports in an isolated JavaScript execution environment, and run deterministic smoke tests. Clearly label such checks as *isolated smoke tests*, not the complete Node test suite. The permanent agent-playtest script is the reproducible reference implementation and should be run in a real Node environment or CI when possible.

## What the playtest harness does
`scripts/agent-playtest.js` controls seat 0 with the strategic drafting policy, plays against three strategic drafting bots, advances the full deterministic match, and records combat duration, timeouts, ranking, draft picks and selected unit configuration. It is a headless scripted agent, **not** a browser-clicking or language-model-driven player. Use custom seeded combat scenarios to inspect tactical movement and interception; match completion alone does not validate AI movement quality.

## After gameplay changes
1. Add focused regression tests for the altered behavior.
2. Run `npm test` and the agent playtest when execution is available.
3. Report actual commands, seed counts, failures, timeouts, and unverified behavior.
4. Update the visible prototype label in `index.html`, the version in `build.json`, and module import cache identifiers when shipping a new playable version.
5. Commit and provide the GitHub commit link. GitHub Pages may deploy asynchronously; don't claim the live page has updated without verifying.

## Collaboration preferences
Make sensible implementation decisions without frequent interruptions. Batch related work. Prefer reproducible seeded tests and root-cause fixes. Preserve performance on low-end Android devices. Do not claim tests passed unless they executed.

## Navigation and timeout diagnostics
Run `npm run diagnose:navigation -- 8 1` for seeded strategic matches plus fixed terrain scenarios. Add `--json` for per-unit movement traces and timeout classifications. The combat engine's opt-in `battle.diagnostics={units:{}}` collects idle frames, blocked frames, path replans, waypoint changes, stuck events, reversals, collision displacement loss, attack opportunities, shots, damage, and sampled positions. Diagnostics are disabled in normal gameplay. Treat timeout classifications as hypotheses, not proven causes. Use the fixed Central Barrier bruiser scenario as a known regression until it clears reliably.

Navigation regression gates: `npm run diagnose:navigation -- 8 1` exits unsuccessfully when a pursuer remains physically immobilized for 3 simulated seconds or any stationary-target fixture fails to find an attack position. Prioritize the obstacle collision shell regression test: obstacle resolution must only correct actual overlaps, never pull a valid unit backwards within an arbitrary near-wall buffer. Tests use combat line of sight plus attack range, not padded navigation line of sight, to determine objective completion. Timeout totals alone are not a failure: defensive combat may legitimately last 30 seconds.

## Physical projectile combat (Prototype 2.0)
Ranged attacks now create projectiles in `battle.projectiles` with deterministic fixed-step travel and swept segment collision. `advanceProjectiles(state, dt, attacks)` resolves earliest collisions against expanded obstacle rectangles, the arena boundary, and the first hostile chassis encountered, rather than applying hit damage at launch. Friendlies do not intercept. Piercing permits one additional enemy per stack but never ignores walls; multishot has independent spread shots sharing a per-volley hit set. Projectile `area` increases collision radius. Only actual impacts generate damage/impact events. The browser renders live state projectiles, not timed cosmetic tracers. Keep projectile physics in `src/simulation.js` and verify with the dedicated projectile regression tests in `tests/simulation.test.js`. Melee remains immediate.

## Prototype 2.1 — Curated modules, utility copies, combat reports
Shared draft offers can repeat; do not deduplicate cards in the common pool. Flat attack-stat cards (damage, health, speed, range, rate) have been removed from `ATTACK_MODULES` in `src/headless.js`, but internal chassis stats and old stat mod fields remain for compatibility. Behavioral attacks (multishot, piercing, area, knockback, taunt), targeting weights, and other mechanics still draft normally. Utility cards occupy one of two passive/utility slots; second copy strengthens the existing slot to 2 and halves base cooldown, with no third copy allowed on the same chassis. Doubling no longer scales movement distance. Nonstacking passives are unique per chassis; `canEquip` gates both bot and human slot choices. Duplicate shared offers may be taken by other players even if one character cannot equip them.
Combat units keep minimal always-on `combatStats` counters for damage dealt/taken, attacks, projectile shots/hits, wall impacts and interceptions. `completeCombat` snapshots `combatReport`; the browser shows a compact fighter breakdown plus team totals after each round. Projectile collision emits `wallImpact` separately from unit impact; canvas renders a 0.16s four-ray spark, no particles engine. Run `npm test`, agent playtests, and navigation diagnostics to guard the mechanics.

## Prototype 2.2 — Tactical reactions
`tacticalAssessment` computes imminent projectile/melee threats, danger, opportunity to finish a target, pursuit/retreat conditions, and endangered allies, once per fighter/tick in combat. `reactToThreat` executes emergency Dodge (safe perpendicular roll + brief evade) and conditional, cooldown-controlled Haste (+40% movement speed for 1.5s, 5s cooldown), Focus (35% faster attack cycle for 1.5s when a kill opportunity is predicted, 6s cooldown), and Bulwark (+5 defense for 2s before a dangerous engagement, 6s cooldown). These three passives no longer apply permanent stat bonuses. Dodge's second copy retains half cooldown; other utilities use the assessment for tactical gating, urgent Intercept bypasses generic position-score threshold. All reactions remain deterministic; no engine/rendering dependency added.
`ensureDraftChoice` only replaces an unusable shared offer if the current player has no legal card left; deliberately duplicated usable offers remain contested. The compact round report records ability activation, successful projectile hits after evasion, blocked attacks, and damage prevention. The fixture tests require a projectile that misses to *not* cause Dodge. Run test suite, seeded agent playtests and navigation diagnostic checks before changing timing or reaction priorities.

## Prototype 2.3 — Reaction timing playtest
The tactical reaction pass uses explicit impending-hit timing. Dodge only considers incoming physical projectile hits within .26s and waits until within .20s to roll, or for an attacker-focused imminent melee swing. Side selection prefers fewer projected hits; a partial roll may still use .13s evasion. Focus requires a plausible multi-attack kill during its burst window, and does not trigger for trivial one-hit kills. Bulwark braces when imminent damage exceeds max(8, 5.5% of current health) or when surrounded. Continue measuring reaction usefulness in headless fights before making further changes. For reproducibility, compare 10 seeded 12-fighter battles with two reactive units per squad and inspect `combatStats.dodges`, `combatStats.evaded`, `combatStats.focus`, `combatStats.bulwark`, and `combatStats.prevented`. In seed-1-through-10 comparison, Dodge rolls decreased 174→128 while registered evaded attacks increased 10→50. Those totals do not include attacks avoided entirely by displacement. 64 isolated tests passed, eight agent matches completed. A 3s pursuit flag at seed 8 round 3 also reproduces on the earlier Prototype 2.2 baseline, so it predates this tuning. Do not silently claim all navigation flags vanished.

## Prototype 2.4 — Attack Geometry & Commitment
The simulation now uses chassis-specific deterministic attack cycles in `src/simulation.js`: Bruiser windup .30s / recovery .22s, Rogue .14s / .10s, Ranged .24s / .18s. `ATTACK_TIMING` also defines windup/recovery movement multipliers and facing-lock at 50% windup. Chassis facing is persistent and follows targets while idle. Attacks start in range, slow movement during windup, emit one `attackCommit` event as facing locks, release at windup completion, then recover before resuming full movement. Attack cooldown still independently limits repeat starts. Dodge can interrupt windup with a brief retry penalty; committed attacks never silently retarget after direction lock.
Melee release uses `meleeAttackTargets` against enemies actually inside the locked facing footprint: Bruiser 58-unit reach / 110° sweep, Rogue 60-unit reach / 35° thrust. Target radii count toward reach, terrain blocks, each enemy is hit at most once per release, and piercing increases enemy count. Multishot adds spread lanes; Area adds 12° and 9 reach per stack. Ranged projectiles retain swept physics, but launch only after ranged windup and along committed facing. `combatStats.attacks` counts actual releases, not abandoned windups. Browser draws a single ~0.14s colored arc/thrust outline or ranged aim line from the `attackCommit` event, without assets or a new graphics engine.
Regression tests cover release delay, directional geometry, locked direction, hit substitution, movement penalties, attack commitment cue, Dodge interruption, projectile physics, and old timing-dependent mechanics. Last verification: 72 isolated JS tests, 8 scripted matches (98 combats), 8-match navigation diagnostics (95 combats) with no flagged stalls and all six stationary-target fixtures passing. Bare-chassis ranged vs melee duels over 30 seeds remained melee-favored in both old and new versions; do not claim the attack timing pass alone solves balance. Check Node CI separately where possible.

## Prototype 2.5 — Translucent attack cues
In `src/game.js`, the browser-only `attackCommit` visualization replaces Prototype 2.4's colored outlines with compact, translucent white filled shapes: a short annular sweep for Bruiser, a tapered thrust for Rogue, and a narrow aim flash for Ranged. Each cue starts at 50% opacity and fades over the existing 0.14s visual-event lifetime. Combat engine timing, hit geometry, facing lock, attack events, and damage are unchanged. The change is cosmetic; verify the effect visually in a browser, particularly with multiple simultaneous attacks. Release metadata and module cache identifiers use `2026-11-22-attack-cues-25` / `attack-cues-25`. The Node suite was not executed for this visual-only change; don't treat that as a passing test run.

## Prototype 2.6 — Melee chassis tuning
Bruiser base damage increases 13→16 while its unmodified facing sweep narrows 110°→95°. Rogue windup lengthens .14→.18s and recovery .10→.12s to make rapid melee attacks slightly more committed. Chassis movement speeds, cooldown intervals, targeting, and module behavior remain unchanged. Bruiser attacks still affect only one target by default; Piercing determines additional target count, while Multishot spreads eligible lanes. Added targeted regression tests for the narrower angle and Piercing-dependent multi-target behavior. Release cache identifier is `2026-11-22-balance-26` (module imports: `balance-26`). The intention is to improve Bruiser hit value without inherent cleave or unrestricted pursuit; actual win-rate/balance effects require seeded simulation verification.

## Prototype 2.6.1 — Draft terminology cleanup
Player-facing categories are now Utility (all cards occupying one of the two shared utility slots, including mechanically passive Regen/Bulwark/Haste/Focus), Attack (attack characteristics), Targeting (AI weight upgrades), and Recruit (new chassis). The engine retains internal `kind:'passive'` and `unit.passives` identifiers for compatibility; their UI names and selectors say Utility. Existing modifiers, timing, eligibility, slots, and draft odds are unchanged. Do not conflate Area with the old Range upgrade: Area gives melee +9 reach and +12° arc per stack, but ranged projectiles gain +3 collision radius and no extra travel distance. Current build tag `2026-11-22-draft-labels-261` (module import cache tag `draft-labels-261`).

## Prototype 2.7 — Composable attack profiles
Attack cards now include Range (+8 reach per stack for melee and projectiles), Sunder (temporary defense reduction), Precision (healthy-target opener), Expose (next different allied fighter consumes a marked target for bonus damage), Disruption (short movement slow), Momentum (up to 100 actual world units of movement over 2 seconds contributes to attack damage regardless of movement direction), Chain (20% of damage redirected per stack to one nearby enemy; lost if none is available; never recursively chains), Burning (refreshable damage over time), Hazardous (temporary damaging ground patches), and Restless (temporary penalty for reselecting the last struck target). Retaliation is a shared-slot Utility, priming the next attack after receiving a landed direct melee hit. Chassis base attack timing is unchanged.
Engine status effects are stored on combat units, and short-lived hazard zones on the battle. Indirect effects never create recursive hits or additional on-hit effects. Damage propagation is deterministic, rendered with lightweight canvas links and circles, and bounded for mobile performance. Behavioral Restless modifies the existing target score with a temporary penalty rather than replacing the targeting AI. Combat modules retain their engine keys for compatibility. Ranged and melee Range are now both +8 per stack; Area independently changes melee arc/reach or ranged collision radius. Build and module cache: `2026-11-22-attack-effects-27` / `attack-effects-27`. Regression fixtures cover range, redistribution, statuses and target switching. Run Node CI, seeded playtests and real-device readability checks before declaring balance.

## Prototype 2.7.1 — Damage-over-time visual feedback
Fractional burning and hazardous damage was already applied to HP and combat stats each 30 Hz simulation step, but the browser rounded each floating damage event to an integer, producing repeated -0 labels. The engine now tags exclusively environmental damage events as `dotDamage`, including a stable target ID. The browser accumulates these events per target into a fractional floating readout every 0.4s, without altering damage timing, DPS, status duration, or scoring. Direct hits retain their normal readouts. Regression tests verify the fractional HP deductions and tagged events. The browser's pending readouts reset between combats. Build `2026-11-23-dot-readouts-271` / module cache `dot-readouts-271`.

## Prototype 2.8 — Progressive squad-size base-stat scaling
Fielding additional chassis applies a shared 15% reduction per extra fighter to **each** chassis's **base** HP and attack damage: 1 fighter=100%, 2=85%, 3=70%. Apply before additive module bonuses (HP +20 per module and Damage +2 per module remain full value); do not modify defense, range, movement speed, cooldowns, attack commitment/recovery, DoT damage or module effects. A unit's squad count is captured in `spawn()` from its owner's deployed squad and passed into `stats(u)` as `squadSize`, defaulting to one for standalone fixtures. Recruiting affects the entire owner's squad on the **next combat spawn**, not mid-battle. The browser inspector displays the applicable base HP/damage multiplier and scaled statistics. Bot recruitment scoring now acknowledges the opportunity cost rather than automatically preferring a second or third chassis. Targeted tests cover all three squad sizes, every chassis, deployment, and undiminished module bonuses. Build `2026-11-23-squad-scaling-28`; cache identifier `squad-scaling-28`. Isolated JS fixtures and seeded full-match playtests are distinct from the Node CI suite and browser visual verification.

## Prototype 2.8.1 — Module text consistency audit
A player-facing text-only pass aligns all 37 catalog cards with their implemented simulation effects. The short draft label and detailed text now share the same source file (`src/module-info.js`) via `cardSummary()` and `cardDetail()`; every card is explicitly covered by both lookup tables and regression tests. Clarifications include: Sunder applies to later attacks, not the hit applying it; Expose requires a different ally; Chain redirects rather than duplicates damage and secondary defense still applies; Hazardous creates at most two simultaneous patches per attacker (overlapping patches can deal separate damage); damage-over-time ticks ignore defense and do not retrigger on-hit effects; Restless changes existing targeting preference temporarily; Range and Area remain distinct; Recruit cards disclose the 15% per extra fighter base HP/damage penalty. Utility cooldowns, slots and duplicate upgrades use consistent wording. The engine's internal `passive` identifiers remain unchanged, and no combat logic, module balance, or draft odds have been altered. Build `2026-11-23-module-copy-281`, browser cache `module-copy-281`.

## Prototype 2.9 — Contextual and explainable bot drafting
Bot drafting in `src/draft-ai.js` now uses explainable component scoring rather than mostly static card ranks. Every candidate is evaluated against current modules, targeting weights, allies, available utility slots/replacements, diminishing returns from repeated upgrades and recruitment's squad-stat opportunity cost. Symmetric interactions include Piercing/Multishot, Hazardous/Disruption, Area/Chain, Restless/Burning, Restless/Expose and Momentum/mobility. Existing behaviors may conflict without hard bans. Each bot has a stable per-match, per-seat, seed-derived soft preference vector over mobility, control, survival, focus fire, teamwork and coverage. This does not advance game RNG. A small seeded variation avoids rigid builds. `evaluateDraft()` produces numeric components and human-readable top reasons; `scoreDraft()` retains its existing API; `chooseCpuDraft()` returns a full explanation. Optional reasoning supplied to `assign()` is saved with draft history and surfaced in the browser. Agent playtest captures explanations. Combat mechanics and squad scaling were not altered. Build `2026-11-23-draft-reasoning-29`; cache `draft-reasoning-29`.

## Prototype 2.9.1 — Per-module damage attribution telemetry
`src/simulation.js` now records per-fighter `combatStats.moduleDamage` for directly measurable damage attributable to Precision, Momentum, Expose, Retaliation, Sunder (credited to the fighter receiving the defense benefit), Chain (actual secondary damage), Burning and Hazardous. Attribution respects actual HP damage and overkill, aggregates fractional environmental ticks, and does not affect combat logic. `combatStats.moduleHits` separately reports actual damage from attacks reaching enemies through extra projectile lanes, additional piercing targets, expanded Area geometry or extra Range; these values can overlap with each other, baseline damage and bonus damage and **must not be summed as additional damage**. `chainRedirected` reports the primary damage diverted by Chain, a cost rather than a benefit, and is distinct from secondary damage actually dealt. Effects without mechanically isolatable extra damage (target priorities, knockback, taunt, slows, mobility, defense, cooldown reduction, etc.) are intentionally not assigned invented numbers; controlled counterfactual tests are needed to estimate their causal value. The round report exposes `moduleDamage`, `moduleHits` and `chainRedirected`; the browser round summary shows module damage and delivery-enabled hits; `scripts/build-audit.js` aggregates both categories and includes per-fighter attribution in standouts. Regression fixtures verify direct contribution math, DoT attribution, overkill caps, chaining, and report exposure. Build `2026-11-23-module-telemetry-291`, cache `module-telemetry-291`.

## Prototype 2.10 — Attack module classification and aftermath activation
The authoritative `ATTACK_STAGES` registry in `src/simulation.js` classifies all 15 attack modifiers as shape, impact, aftermath, condition or targeting. Shape modules affect the hit footprint (lanes, piercing, area, reach, chain); impact modules change the target (knockback, taunt, sunder, expose, disruption); conditions modify raw damage (precision, momentum); aftermath persists (burning, hazardous); targeting affects next target preference (restless). The registry is reflected in short and detailed card descriptions without introducing restrictive draft pools. `claimAttackEffect(source,key,attackId,now)` implements independent **1-second per-chassis** activation cooldowns for Burning and Hazardous. Every impact from a single committed melee release or projectile volley shares an attack ID; a multi-target release can apply effects to all impacted enemies, including later projectile arrivals. Other attacks during that module's cooldown do not apply or refresh its aftermath. The two aftermath cooldowns do not interfere with each other. Direct conditional damage, attack geometry, Sunder and other impact effects still resolve on qualifying hits. Environmental DoT and secondary Chain hits still cannot recursively apply procs. Telemetry is preserved. `nextAttackId` is allocated on attack release (and for test-created volleys) to group impacts. The full resolver is not yet rewritten into independently registered effect callbacks; classification and explicit proc lifecycle establish the common semantics while preserving proven combat logic. Tests cover registry coverage, per-fighter cooldowns, grouped multi-target releases, later volley hits and independent conditions. Build `2026-11-23-attack-pipeline-210` / cache `attack-pipeline-210`.

## Prototype 2.11 — Persistent aftermath vs positional impact
Classified Taunt, Sunder, Disruption and Expose as `aftermath` alongside Burning and Hazardous, leaving Knockback and Follow Through as `impact` effects. Converted old `utility:followthrough` and `utility:disengage` into freely stackable attack modules (`attack:followthrough`, `attack:disengage`). They no longer occupy one of the two utility/passive slots, and their old autonomous utility mobility branches were removed.

Follow Through now triggers **only after a qualifying actual hit** with an internal 0.75s cooldown and at most one movement per attack release. Melee attackers move through and land just beyond the struck target (temporarily ignoring only its collision); ranged attackers advance 18 units toward the struck target, stopping short of its body collision, without any phasing. Additional stacks increase travel by 8 units (up to three extra stacks). Movement is refused if the intended path crosses terrain, other units, or the arena boundary. Ranged attackers *can* draft Follow Through deliberately as an off-meta approach tactic.

Disengage now starts on **attack release** (successful hit not required) and forces a half-second safety-focused retreat away from nearby enemies, ignoring ordinary targeting/approach preferences; it suppresses new attack initiation while active and then clears the old target and path so combat AI reassesses normally. Additional stacks increase retreat speed by 10% each, capped at +35%; duration remains 0.5s. It works on both melee and ranged. The attack score AI and UI inspector reflect both modules in their new classifications. Existing numerical damage, DoT, and squad scaling rules remain unchanged.

Attack geometry, conditional damage, on-hit statuses and cooldowns remain in their existing code locations; the explicit stage registry is the source of truth for classifications, not a completely independently registered effect-pipeline yet. Focused regressions cover first-hit/single-release behavior, movement collisions and ranged approach, cooldowns, stage/draft coverage and retreat. Build `2026-11-23-attack-reclass-211`; client cache `attack-reclass-211`.

## Prototype 2.11.1 — Strict Follow Through displacement limit
Follow Through is bounded by movement budget: **melee 72 units**, **ranged 18 units**, plus **8 per additional stack** (up to 3 bonus stacks). Melee passes through the chosen enemy only if the total near-to-far traversal fits within that budget; otherwise it advances only to the enemy's near-side collision clearance. Ranged cannot phase through targets. Crossing the arena boundary, terrain, or any unrelated fighter is disallowed; it never teleports to the far side from an arbitrary distance. For multi-target attacks, select the **deepest successfully hit target by projected depth along the committed attack's original direction**, with stable target-id tie-breaking. Group all melee hits at release and accumulate projectile hits through the entire volley until the final projectile expires before triggering a single Follow Through movement. Later hits in a volley therefore cannot create ping-pong motion. Keep the 0.75s internal cooldown. New tests cover distance bounds, deep target selection, and delayed projectiles. Build `2026-11-23-followthrough-budget-2111` / browser import cache `followthrough-budget-2111`.
